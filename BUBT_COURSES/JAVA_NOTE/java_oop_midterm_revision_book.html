01 Java Architecture & Platform Independence

Must For Exam

সহজ বাংলা সামারি (Concept Clarification):

জাভাকে বলা হয় Platform Independent ("Write Once, Run Anywhere - WORA")। কারণ javac কম্পাইলার জাভা কোডকে কোনো নির্দিষ্ট মেশিনের মেশিন কোডে রূপান্তর না করে Bytecode (.class file) এ রূপান্তর করে। এই বাইটকোড যেকোনো অপারেটিং সিস্টেমের (Windows, Mac, Linux) নিজস্ব JVM (Java Virtual Machine) চালাতে পারে।

1. JVM (Java Virtual Machine)

একটি ভার্চুয়াল ইঞ্জিন যা বাইটকোডকে পড়ে মেশিনের নিজস্ব ইন্সট্রাকশনে রান করে। এটি সফটওয়্যার ভিত্তিক এবং Platform Dependent (উইন্ডোজের জন্য আলাদা JVM, ম্যাকের জন্য আলাদা)।

2. JRE (Java Runtime Env.)

JRE = JVM + Class Libraries (যেমন: rt.jar) + Other Files। এটি জাভা কোড রান করার পরিবেশ দেয়। এটি ফিজিক্যালি এক্সিস্ট করে।

3. JDK (Java Dev. Kit)

JDK = JRE + Development Tools (javac, java, jar, javadoc)। জাভা সফটওয়্যার বানানোর পূর্ণ প্যাকেজ হলো JDK।

Q1: Why is Java platform independent but JVM is platform dependent?
উত্তর: জাভা সোর্স কোড কম্পাইল হয়ে তৈরি করে .class বাইটকোড—যা সব প্ল্যাটফর্মের জন্য হুবহু একই (Platform Independent)। কিন্তু উইন্ডোজ ও লিনাক্সের হার্ডওয়্যার আর্কিটেকচার ভিন্ন, তাই উইন্ডোজের জন্য তৈরিকৃত JVM সরাসরি লিনাক্সে চলতে পারে না। প্রতিটি ওএস-এর বাইটকোডকে নিজের মেশিনের ভাষায় অনুবাদের জন্য নিজস্ব কাস্টমাইজড JVM লাগে, তাই JVM হলো Platform Dependent।

02 Java Program Structure, Keywords & Scanner

Lab & Midterm
Dissecting: public static void main(String[] args)
  • public: এক্সেস মডিফায়ার; JVM যেন ক্লাসের বাহির থেকে যেকোনো সময় এই মেথড কল করতে পারে।
  • static: JVM যাতে ক্লাসের কোনো অবজেক্ট (Object) ইনস্ট্যানশিয়েট না করেই সরাসরি ClassName.main() কল করতে পারে।
  • void: মেথডটি সম্পন্ন হওয়ার পর কলারকে (JVM) কোনো ভ্যালু রিটার্ন করে না।
  • main: জাভা প্রোগ্রামের এন্ট্রি পয়েন্ট আইডেন্টিফায়ার যা JVM হার্ডকোডভাবে খুঁজে নেয়।
  • String[] args: কমান্ড লাইন আর্গুমেন্ট গ্রহণ করার জন্য স্ট্রিং অ্যারে।
sc.nextInt()

পূর্ণসংখ্যা (Integer) ইনপুট নেওয়ার জন্য।

sc.nextDouble()

ভগ্নাংশযুক্ত সংখ্যা (Double) ইনপুট নেওয়ার জন্য।

sc.next()

স্পেস ছাড়া শুধু একটি সিঙ্গেল শব্দ ইনপুট নিতে।

sc.nextLine()

স্পেস সহ পুরো একটি বাক্য/লাইন ইনপুট নেওয়ার জন্য।

sc.next().charAt(0)

[ভেরি ইম্পর্ট্যান্ট ট্রিক] ক্যারেক্টার (char) ইনপুট নিতে কোনো সরাসরি nextChar() নেই; তাই প্রথম ইনপুটের ০তম ইনডেক্স ক্যারেক্টার নিতে এটি ব্যবহার করা হয়।

DemoInput.java 
import java.util.Scanner;

public class DemoInput {
    public static void main(String[] args) {
        // Scanner অবজেক্ট তৈরি
        Scanner input = new Scanner(System.in);

        System.out.print("Enter your ID: ");
        int id = input.nextInt();

        System.out.print("Enter your Name: ");
        input.nextLine(); // Clear buffer newline
        String name = input.nextLine();

        System.out.print("Enter first letter of section (Char): ");
        char sec = input.next().charAt(0);

        System.out.println("\n--- Student Details ---");
        System.out.println("ID: " + id + " | Name: " + name + " | Sec: " + sec);
        input.close();
    }
}

03 Class, Object, and Memory Architecture

Core OOP

Class (Blueprint / Template)

ক্লাস হলো একটি লজিক্যাল ব্লু-প্রিন্ট বা নকশা। এটি নিজে মেমোরি দখল করে না। ক্লাসে দুটি প্রধান জিনিস থাকে:
1. State (Fields / Instance Variables): অবজেক্টের তথ্য বা ডেটা ধারণ করে।
2. Behavior (Methods): অবজেক্ট কী কী কাজ সম্পন্ন করতে পারবে তা ডিফাইন করে।

Object (Real Instance in Memory)

অবজেক্ট হলো একটি ক্লাসের ফিজিক্যাল বাস্তবায়ন (Instance)। যখন new কি-ওয়ার্ড দিয়ে অবজেক্ট তৈরি হয়, তখনই Heap Memory-তে এর জন্য জায়গা বরাদ্দ করা হয়।

[ Primitive Variable vs Reference Variable Memory Diagram ]
1. Primitive: int x = 10;
   [ Stack Memory: Variable 'x' সরাসরি মান ধারণ করে -> (10) ]

2. Object Reference: Circle c1 = new Circle(5.0);
   [ Stack Memory ]                          [ Heap Memory (Actual Object) ]
   c1 (Reference Pointer: 0x4A1)  ───────>   ┌───────────────────────────────┐
                                             │ radius: 5.0                   │
                                             │ findArea() { ... }            │
                                             └───────────────────────────────┘

3. Reference Assignment: Circle c2 = c1;
   c2 ও c1 উভয়ই এখন একই মেমোরি এড্রেস (0x4A1) নির্দেশ করবে!
   যদি c2.radius পরিবর্তন করা হয়, তবে c1.radius ও স্বয়ংক্রিয়ভাবে পরিবর্তিত হবে!
StudentTest.java (From Handnote Page 4) 
class Student {
    // Instance variables (State)
    String name;
    int id;

    // Instance method (Behavior)
    void display() {
        System.out.println("Student Name: " + name);
        System.out.println("Student ID  : " + id);
    }
}

public class StudentTest {
    public static void main(String[] args) {
        // অবজেক্ট ক্রিয়েশন (Heap এ মেমোরি এলোকেট হচ্ছে)
        Student s1 = new Student();
        s1.name = "Sohan";
        s1.id = 20255103;
        s1.display();

        // রেফারেন্স কপি এক্সপেরিমেন্ট
        Student s2 = s1; // s2 এখন s1 এর একই মেমোরি অবজেক্টকে নির্দেশ করে
        s2.name = "Resalat";
        System.out.println("s1 Name after s2 change: " + s1.name); // Prints Resalat!
    }
}

04 Garbage Collection in Java

Tricky Theory

গারবেজ কালেকশন কী এবং কখন একটি অবজেক্ট গারবেজ হিসেবে গণ্য হয়?

জাভাতে C++ এর মতো ডেভেলপারকে নিজে হাতে free() বা delete কল করতে হয় না। হিপ মেমোরিতে যদি কোনো অবজেক্টের কোনো বৈধ রেফারেন্স ভেরিয়েবল না থাকে (Unreachable Object), তবে JVM স্বয়ংক্রিয়ভাবে একটি ব্যাকগ্রাউন্ড ডিমন্ড থ্রেডের মাধ্যমে সেই মেমোরি রিলিজ করে দেয়। এটিই Automatic Garbage Collection।

Way 1: By Reassigning Reference

Circle c1 = new Circle();
Circle c2 = new Circle();
c1 = c2;

c1 এর আগের প্রথম অবজেক্টটি আনরিচেবল হয়ে যায় এবং গারবেজ হয়।

Way 2: By Nulling Reference

Circle c1 = new Circle();
c1 = null;

রেফারেন্স নাল করে দিলে হিপের মেমোরিটি সরাসরি গারবেজ কালেকশনের যোগ্য হয়।

05 Constructors, this Keyword & Chaining

100% Exam Common

Rules for Writing Constructor

  • কনস্ট্রাক্টরের নাম এবং ক্লাসের নাম অবশ্যই হুবহু একই (Same Name) হতে হবে।
  • এর কোনো Return Type থাকে না (এমনকি void ও না)।
  • কনস্ট্রাক্টর কখনো abstract, final, static হতে পারে না।
  • আমরা যদি ক্লাসে কোনো কনস্ট্রাক্টর না লিখি, জাভা নিজে একটি অদৃশ্য Default No-arg Constructor যুক্ত করে দেয়।

Why Constructor has No Return Type?

পরীক্ষার জনপ্রিয় প্রশ্ন: কনস্ট্রাক্টর সরাসরি আমাদের কোড দিয়ে কল হয় না; এটি রানটাইমে মেমোরি এলোকেশনের পর স্বয়ংক্রিয়ভাবে নতুন অবজেক্টের প্রাথমিক ভ্যালু সেট (Initialize) করতে এক্সিকিউট হয় এবং ইমপ্লিসিটভাবে নতুন তৈরিকৃত অবজেক্টটিকেই রিটার্ন করে। তাই ইউজার নিজে কোনো রিটার্ন টাইপ ডিফাইন করতে পারে না।

Three Crucial Uses of the this Keyword:
1. Shadowing Resolve: this.name = name; প্যারামিটার ও ইন্সট্যান্স ভ্যারিয়েবলের নাম একই হলে কনফিউশন দূর করে।
2. Constructor Chaining: this(0, 0); একই ক্লাসের এক কনস্ট্রাক্টর থেকে আরেক কনস্ট্রাক্টর কল করে (অবশ্যই প্রথম লাইনে হতে হবে)।
3. Return Current Object: return this; মেথড চেইনিং করার জন্য নিজের অবজেক্টকে মেথড থেকে রিটার্ন করা যায়।
PointChaining.java (From Slide Example) 
public class Point {
    private int x;
    private int y;

    // Default No-argument Constructor
    public Point() {
        this(0, 0); // Constructor Chaining: Calls 2-parameter constructor! (Must be line 1)
        System.out.println("Default origin point initialized.");
    }

    // Parameterized Constructor
    public Point(int x, int y) {
        this.x = x; // this.x নির্দেশ করছে ক্লাসের ফিল্ড, আর ডানপাশের x হলো প্যারামিটার
        this.y = y;
    }

    public void display() {
        System.out.println("Point Coordinates: (" + this.x + ", " + this.y + ")");
    }

    public static void main(String[] args) {
        Point p1 = new Point();       // Calls no-arg which chains to parameterized
        Point p2 = new Point(15, 25); // Directly calls parameterized
        p1.display();
        p2.display();
    }
}

06 Encapsulation & Master Access Modifier Table

Guaranteed 4-5 Marks

এনক্যাপসুলেশন (Encapsulation) কী এবং কেন ব্যবহার করা হয়?

ডেটা (ভ্যারিয়েবল) এবং সেই ডেটার ওপর কাজ করা মেথডগুলোকে একটি একক ক্যাপসুলে (ক্লাস) আবদ্ধ রাখার প্রক্রিয়াকে Encapsulation বলে। এর প্রধান উদ্দেশ্য হলো Data Hiding। ক্লাসের ভ্যারিয়েবলগুলোকে private রেখে পাবলিক Getter এবং Setter মেথডের মাধ্যমে শর্তযুক্ত সুরক্ষিত এক্সেস দেওয়া হয়।

07 Static Keyword & Object Passing in Methods

Handnote Favorite

The static Keyword

স্ট্যাটিক মেম্বার ক্লাসের নিজস্ব প্রপার্টি, কোনো একক অবজেক্টের নয়।
• মেমোরিতে ক্লাস লোড হওয়ার সময় মাত্র একবার জায়গা নেয়।
• অবজেক্ট না বানিয়ে সরাসরি ক্লাসের নাম দিয়ে কল করা যায়: ClassName.methodName()।
• সকল অবজেক্টের মাঝে স্ট্যাটিক ভ্যারিয়েবলের মান শেয়ার্ড (Shared) থাকে।

Passing Objects to Methods

জাভাতে একটি অবজেক্টকে মেথডের প্যারামিটার হিসেবে পাঠানো যায়। যেমন ক্লাসনোটের EBook এবং Rectangle তুলনা: r1.compareArea(r2); // r1 হলো this, r2 হলো প্যারামিটার ob

ObjectPassingDemo.java (Page 34-35 of Handnote) 
class Rectangle {
    double width, length;

    Rectangle(double width, double length) {
        this.width = width;
        this.length = length;
    }

    double area() {
        return length * width;
    }

    // Object passing: প্যারামিটার হিসেবে অন্য একটি Rectangle অবজেক্ট গ্রহণ করছে
    void compareArea(Rectangle r) {
        if (this.area() > r.area()) {
            System.out.println("Rectangle 1 (Caller) has greater area.");
        } else if (this.area() < r.area()) {
            System.out.println("Rectangle 2 (Passed Object) has greater area.");
        } else {
            System.out.println("Both rectangles have identical area.");
        }
    }
}

public class ObjectPassingDemo {
    public static void main(String[] args) {
        Rectangle r1 = new Rectangle(10.0, 5.0); // Area = 50.0
        Rectangle r2 = new Rectangle(20.0, 5.0); // Area = 100.0

        r1.compareArea(r2); // r1 হলো this, r2 হলো r
    }
}

08 Inheritance, IS-A vs HAS-A, & The Diamond Problem

Major Theoretical Question

IS-A vs HAS-A Relationship

  • IS-A (Inheritance): extends কি-ওয়ার্ড দিয়ে অর্জন করা হয়। যেমন: Programmer IS-A Employee, Dog IS-A Animal।
  • HAS-A (Aggregation/Composition): ক্লাসের ভেতরে অন্য ক্লাসের অবজেক্ট রেফারেন্স রাখা। যেমন: Car HAS-A Engine, Employee HAS-A Address।

3 Supported Types in Java (Classes)

  1. Single Inheritance: A ➔ B (একটি প্যারেন্ট, একটি চাইল্ড)।
  2. Multilevel Inheritance: A ➔ B ➔ C (গ্র্যান্ডপ্যারেন্ট ➔ প্যারেন্ট ➔ চাইল্ড)।
  3. Hierarchical Inheritance: A ➔ B এবং A ➔ C (এক প্যারেন্টের একাধিক চাইল্ড)।
Why Java DOES NOT Support Multiple Inheritance with Classes? (The Diamond Problem)

মনে করুন, ক্লাস A এবং ক্লাস B উভয়ের মাঝেই হুবহু একই নামের মেথড void msg() আছে। এখন যদি ক্লাস C একই সাথে A ও B কে ইনহেরিট করতো (class C extends A, B), তবে new C().msg(); কল করলে কম্পাইলার কনফিউজড হয়ে যেত যে সে কোন প্যারেন্টের মেথড রান করবে! একেই বলা হয় Ambiguity / The Diamond Problem। কোড যাতে জটিলতামুক্ত থাকে তাই জাভায় ক্লাসের মাধ্যমে Multiple Inheritance নিষিদ্ধ করা হয়েছে।

// Parent Class
class Person {
    String name; // Parent's variable

    Person(String name) {
        this.name = name;
    }

    void introduce() {
        System.out.println("Full Name: " + this.name);
    }
}

// Child Class extending Person
class Employee extends Person {
    String name; // Shadows parent's 'name' variable (stores nickname)

    Employee(String fullName, String nickName) {
        super(fullName);       // [USE 1]: Parent Constructor call (Must be first statement)
        this.name = nickName;  // Child's own variable
    }

    @Override
    void introduce() {
        super.introduce();     // [USE 2]: Calls overridden parent method
        System.out.println("Nickname: " + this.name);
    }

    void showNames() {
        // [USE 3]: Distinguishing shadowed variables
        System.out.println("Parent Name (via super.name): " + super.name);
        System.out.println("Child Name (via this.name)  : " + this.name);
    }
}

public class SuperMasterDemo {
    public static void main(String[] args) {
        Employee emp = new Employee("Tasniah Mohiuddin", "Tas");
        emp.introduce();
        System.out.println("--------------------");
        emp.showNames();
    }

class Animal {
    void sound() {
        System.out.println("Animal makes a generic sound");
    }
}

class Dog extends Animal {
    @Override
    void sound() {
        System.out.println("Dog says: Woof Woof!");
    }
}

class Cat extends Animal {
    @Override
    void sound() {
        System.out.println("Cat says: Meow Meow!");
    }
}

public class DynamicDispatchTest {
    public static void main(String[] args) {
        // Parent class reference variable
        Animal myAnimal;

        // Points to Dog object at runtime
        myAnimal = new Dog();
        myAnimal.sound(); // Output: Dog says: Woof Woof!

        // Same reference points to Cat object at runtime
        myAnimal = new Cat();
        myAnimal.sound(); // Output: Cat says: Meow Meow!
    }

Q6. Implement Product hierarchy with Electronics (10% discount) and Clothing (20% discount) using super constructor. 

class Product {
    String name;
    double price;

    Product(String name, double price) {
        this.name = name;
        this.price = price;
    }

    double calculatePrice() {
        return price;
    }
}

class Electronics extends Product {
    Electronics(String name, double price) {
        super(name, price);
    }

    @Override
    double calculatePrice() {
        return price - (price * 0.10); // 10% discount
    }
}

class Clothing extends Product {
    Clothing(String name, double price) {
        super(name, price);
    }

    @Override
    double calculatePrice() {
        return price - (price * 0.20); // 20% discount
    }
}

public class StoreMain {
    public static void main(String[] args) {
        Electronics lap = new Electronics("Laptop", 50000);
        Clothing shirt = new Clothing("Shirt", 2000);

        System.out.println(lap.name + " after 10% disc: " + lap.calculatePrice());
        System.out.println(shirt.name + " after 20% disc: " + shirt.calculatePrice());
    }
}
