Topic 01

Class, Object & Access Modifiers (Encapsulation)

১. Class ও Object কী?

Class হলো অবজেক্ট তৈরির একটি ব্লুপ্রিন্ট (Blueprint) বা টেমপ্লেট। আর Object হলো সেই ক্লাসের ওপর ভিত্তি করে মেমোরিতে তৈরি হওয়া বাস্তব সত্তা (Instance)।

  • Encapsulation (এনক্যাপসুলেশন): ডাটা/ফিল্ড এবং সেগুলোর মেথডকে একটি একক ক্লাসে গুটিয়ে রাখা এবং ডাটা গোপনীয়তা নিশ্চিত করা।
  • Data Hiding: ক্লাসের ফিল্ডগুলোকে private করে বাহিরে থেকে মেথড (Getter/Setter) দিয়ে সুরক্ষিতভাবে এক্সেস করা।

২. Java Access Modifiers Table:

Modifier Same Class Same Package Subclass (Diff Pkg) World (Anywhere)
private ✅ Yes ❌ No ❌ No ❌ No
default (no modifier) ✅ Yes ✅ Yes ❌ No ❌ No
protected ✅ Yes ✅ Yes ✅ Yes ❌ No
public ✅ Yes ✅ Yes ✅ Yes ✅ Yes
💡 Exam Favorite Question: "Encapsulation কীভাবে অর্জন করা হয়?"
উত্তর: ১. Instance variable গুলোকে private ঘোষণা করে।
২. ডাটা রিড/রাইট করার জন্য public getter এবং setter মেথড প্রদান করে।
BankAccount.java (Class & Encapsulation) JAVA 
class BankAccount {
    // Private variables (Data Hiding)
    private String accountNumber;
    private double balance;

    // Constructor
    public BankAccount(String accountNumber, double initialBalance) {
        this.accountNumber = accountNumber;
        if (initialBalance >= 0) {
            this.balance = initialBalance;
        } else {
            this.balance = 0;
        }
    }

    // Getter for Balance
    public double getBalance() {
        return balance;
    }

    // Deposit method with validation
    public void deposit(double amount) {
        if (amount > 0) {
            balance += amount;
            System.out.println("Deposited: $" + amount);
        } else {
            System.out.println("Invalid amount!");
        }
    }
}

public class Main {
    public static void main(String[] args) {
        BankAccount acc = new BankAccount("ACC-101", 500.0);
        
        // System.out.println(acc.balance); ❌ COMPILE ERROR! Direct access not allowed
        
        acc.deposit(200.0);
        System.out.println("Current Balance: $" + acc.getBalance());
    }
}
Expected Output:
Deposited: $200.0
Current Balance: $700.0

Topic 02

Constructors & Constructor Overloading

কনস্ট্রাক্টর কী?

কনস্ট্রাক্টর হলো একটি বিশেষ ধরণের মেথড যা নতুন অবজেক্ট তৈরির সময় (মেমোরি অ্যালকেশনের ঠিক পরপরই) ফিল্ডসমূহ ইনিশিওলাইজ করতে ব্যবহৃত হয়।

  • নামকরণ: কনস্ট্রাক্টরের নাম অবশ্যই তার ক্লাসের নামের অবিকল একই হতে হবে।
  • No Return Type: এর কোনো void সহ রিটার্ন টাইপ থাকে না।
  • Automatic Invocation: new কিওয়ার্ড দিয়ে অবজেক্ট তৈরি হলেই এটি রান করে।
💡 Exam Question: "আমরা কোনো Constructor না লিখলে কী ঘটে?"
উত্তর: Java Compiler নিজে থেকেই একটি Default No-arg Constructor ক্লাসে যোগ করে দেয়। কিন্তু আপনি যদি নিজের হাতে কোনো Parameterized Constructor লেখেন, তখন কম্পাইলার আর Default Constructor যোগ করে না!
⚠️ Private Constructor: কনস্ট্রাক্টর private করা হলে বাইরের কোনো ক্লাস থেকে new দিয়ে অবজেক্ট তৈরি সম্ভব নয়। এটি Singleton Pattern এবং Utility Class এর জন্য ব্যবহৃত হয়।
Book.java (Constructor Overloading Example) JAVA 
class Book {
    String title;
    double price;

    // 1. Default Constructor
    Book() {
        title = "Untitled";
        price = 0.0;
    }

    // 2. Parameterized Constructor
    Book(String t, double p) {
        title = t;
        price = p;
    }

    void displayInfo() {
        System.out.println("Book: " + title + " | Price: $" + price);
    }
}

public class Main {
    public static void main(String[] args) {
        Book b1 = new Book();                  // Calls Default
        Book b2 = new Book("Java OOP", 45.0);  // Calls Parameterized

        b1.displayInfo();
        b2.displayInfo();
    }
}
Expected Output:
Book: Untitled | Price: $0.0
Book: Java OOP | Price: $45.0

Topic 03

static Keyword & Static Blocks

static কিওয়ার্ডের মূল ধারণা:

static সদস্যগুলো (Variable, Method, Block) কোনো নির্দিষ্ট অবজেক্টের অংশ নয়; তারা সরাসরি **Class Level** সদস্য।

  • Static Variable: ক্লাসের সব অবজেক্টের জন্য একটি মাত্র শেয়ার্ড মেমোরি কপি তৈরি হয়।
  • Static Method: অবজেক্ট ক্রিয়েট না করেই সরাসরি ClassName.methodName() দিয়ে কল করা যায়।
  • Static Block: ক্লাসটি যখন JVM এ লোড হয় (main method রান হওয়ার আগেই) একদম প্রথমবার এটি অটোমেটিক এক্সিকিউট হয়।
🚨 Static Limitations (পরীক্ষায় খুব জনপ্রিয় প্রশ্ন):
১. Static Method সরাসরি কোনো Non-static (Instance) Variable বা Method কে ব্যবহার করতে পারে না।
২. Static context-এ this এবং super কিওয়ার্ড ব্যবহার করা সম্পূর্ণ নিষিদ্ধ!
StaticDemo.java JAVA 
class Student {
    String name;                   // Instance variable
    static String university = "UIU"; // Shared static variable
    static int studentCount = 0;   // Counter

    // Static Block
    static {
        System.out.println(">>> Static Block Executed (Class Loaded) <<<");
        studentCount = 100; // Initial setup
    }

    Student(String n) {
        this.name = n;
        studentCount++;
    }

    static void showTotal() {
        System.out.println("Total Students registered: " + studentCount);
        // System.out.println(name); ❌ ERROR! Static method cannot access non-static 'name'
    }
}

public class Main {
    public static void main(String[] args) {
        System.out.println("Main method started execution.");
        Student s1 = new Student("Kaesar");
        Student s2 = new Student("Arafat");

        Student.showTotal();
        System.out.println(s1.name + " studies at " + Student.university);
    }
}
Expected Output:
>>> Static Block Executed (Class Loaded) <<<
Main method started execution.
Total Students registered: 102
Kaesar studies at UIU

Topic 04

this Keyword & Constructor Chaining

this কী?

this হলো একটি রেফারেন্স ভ্যারিয়েবল যা বর্তমান মেমোরি অবজেক্টের (Current Instance) অ্যাড্রেস ধারণ করে।

this এর ৩টি প্রধান ব্যবহার:

  1. Variable Shadowing সমাধান: Instance variable এবং Parameter এর নাম একই হলে this.variableName দিয়ে পার্থক্য করা হয়।
  2. Current Method Invocation: বর্তমান ক্লাসের কোনো মেথডকে স্পষ্ট করার জন্য call করা।
  3. Constructor Chaining (this()): একই ক্লাসের এক কনস্ট্রাক্টর থেকে অন্য কনস্ট্রাক্টরকে ইনভোক করা।
📌 Golden Rule for this():
কনস্ট্রাক্টর চেইনিংয়ের জন্য this(...) ব্যবহার করলে সেই স্টেটমেন্টকে অবশ্যই কনস্ট্রাক্টরের **একদম প্রথম লাইনে (First Statement)** হতে হবে!
Circle.java (this & Constructor Chaining) JAVA 
class Circle {
    double radius;
    String color;

    // 1. No-arg Constructor
    Circle() {
        this(1.0, "Red"); // Calls the 2-arg constructor (Chaining)
        System.out.println("Default constructor finished.");
    }

    // 2. Parameterized Constructor
    Circle(double radius, String color) {
        this.radius = radius; // Shadowing resolved
        this.color = color;
    }

    void display() {
        System.out.println("Circle Radius: " + this.radius + ", Color: " + this.color);
    }
}

public class Main {
    public static void main(String[] args) {
        Circle c1 = new Circle(); // Uses chaining
        c1.display();
    }
}
Expected Output:
Default constructor finished.
Circle Radius: 1.0, Color: Red

Topic 05

Inheritance & Class Relationships (IS-A vs HAS-A)

ইনহেরিটেন্স (Inheritance) কী?

একটি ক্লাস (Child / Subclass) যখন অন্য ক্লাসের (Parent / Superclass) প্রপার্টি ও মেথডগুলো গ্রহণ করে, তাকে Inheritance বলে। Java-তে extends কিওয়ার্ড ব্যবহার করা হয়।

  • IS-A Relationship (Inheritance): Dog IS-A Animal, Car IS-A Vehicle.
  • HAS-A Relationship (Aggregation/Composition): Car HAS-A Engine. (একটি ক্লাসের ফিল্ড হিসেবে অন্য ক্লাসের অবজেক্ট থাকা)।
❌ Why Java doesn't support Multiple Inheritance with Classes:
যদি ক্লাস A এবং B উভয়েই display() মেথড রাখে, এবং C যদি A, B উভয়কে ইনহেরিট করে, তবে C এর অবজেক্ট display() কল করলে কোনটির মেথড রান হবে তা নিয়ে দ্বিধা তৈরি হয়। একে Diamond Problem বলে।
InheritanceCompositionDemo.java JAVA 
// HAS-A Relationship Component
class Engine {
    void start() {
        System.out.println("Engine is roaring...");
    }
}

// Superclass
class Vehicle {
    int maxSpeed = 120;
}

// Subclass (IS-A Vehicle) + HAS-A Engine
class Car extends Vehicle {
    Engine engine = new Engine(); // HAS-A Relationship

    void drive() {
        engine.start(); // Using engine
        System.out.println("Car driving at speed up to: " + maxSpeed + " km/h");
    }
}

public class Main {
    public static void main(String[] args) {
        Car myCar = new Car();
        myCar.drive();
    }
}
Expected Output:
Engine is roaring...
Car driving at speed up to: 120 km/h

Topic 06

Method Overloading & Automatic Type Promotion

মেথড ওভারলোডিং কী?

একই ক্লাসে যদি একই নামের একাধিক মেথড থাকে, কিন্তু তাদের **প্যারামিটার লিস্ট** (Parameter Count বা Parameter Data Types) ভিন্ন হয়, তাকে Method Overloading বলে। এটি Compile-time Polymorphism (Static Binding)।

Automatic Type Promotion Rules:

ম্যাচিং ডেটা টাইপ না পাওয়া গেলে Java ছোট টাইপকে বড় টাইপে অটোমেটিক প্রমোট করে:

byte → short → int → long → float → double, এবং char → int.

🚨 Ambiguity in Overloading:
যদি কোনো ওভারলোডেড মেথড থাকে add(int, double) এবং add(double, int), আর আপনি কল করেন add(10, 20), তবে Java Ambiguity Error দিবে কারণ দুটি মেথডই সমানে সম্ভাব্য!
TypePromotion.java JAVA 
class MathUtil {
    void show(int a, double b) {
        System.out.println("int, double version called");
    }

    void show(double a, double b) {
        System.out.println("double, double version called");
    }
}

public class Main {
    public static void main(String[] args) {
        MathUtil util = new MathUtil();
        
        // 10 is int, 5.5 is double -> Matches 1st
        util.show(10, 5.5); 
        
        // Both integers (10, 20) -> 20 is promoted to double to match 1st!
        util.show(10, 20); 
    }
}
Expected Output:
int, double version called
int, double version called

শুধু Return Type পরিবর্তন করে কি দুটি মেথড ওভারলোড করা যায়? কেন?

না, কখনই সম্ভব নয়! কারণ প্রোগ্রাম যখন মেথড কল করে (যেমন: calculator.add(5, 10)), তখন রিটার্ন টাইপ দেখে বোঝার কোনো উপায় থাকে না যে কোন মেথডকে কল করা হয়েছে। তাই কম্পাইল এরর হবে।

Topic 07

Method Overriding & Dynamic Method Dispatch

মেথড ওভাররাইডিং কী?

Subclass যদি Superclass-এর কোনো মেথডকে **একই নাম, একই প্যারামিটার এবং একই/Covariant রিটার্ন টাইপ** দিয়ে পুনরায় নিজের মতো ডিফাইন করে, তাকে Overriding বলে। এটি Runtime Polymorphism (Dynamic Binding)।

Dynamic Method Dispatch (Upcasting):

প্যারেন্ট ক্লাসের রেফারেন্স দিয়ে চাইল্ড ক্লাসের অবজেক্ট ধরে রাখলে, Runtime-এ আসল অবজেক্টের মেথডই এক্সিকিউট হবে:

Parent obj = new Child(); → obj.speak(); (Calls Child's speak!)

💡 Non-overrideable Methods:
১. static methods (মেথড হাইডিং ঘটে, ওভাররাইডিং নয়)।
২. final methods (পরিবর্তন নিষিদ্ধ)।
৩. private methods (চাইল্ড ক্লাস থেকে অদৃশ্য)।
PolymorphismDemo.java JAVA 
class Bank {
    double getRateOfInterest() {
        return 0.0;
    }
}

class BRACBank extends Bank {
    @Override
    double getRateOfInterest() {
        return 8.5;
    }
}

class DBBLBank extends Bank {
    @Override
    double getRateOfInterest() {
        return 9.0;
    }
}

public class Main {
    public static void main(String[] args) {
        // Dynamic Method Dispatch
        Bank myBank;

        myBank = new BRACBank();
        System.out.println("BRAC Interest: " + myBank.getRateOfInterest() + "%");

        myBank = new DBBLBank();
        System.out.println("DBBL Interest: " + myBank.getRateOfInterest() + "%");
    }
}
Expected Output:
BRAC Interest: 8.5%
DBBL Interest: 9.0%
📝 Practice Task 7

চাইল্ড ক্লাসে মেথড ওভাররাইড করার সময় Access Modifier কি সংকুচিত (Narrow) করা সম্ভব? (যেমন Parent এ public কিন্তু Child এ private)?

না! Overriding-এর নিয়ম হলো চাইল্ড ক্লাসের মেথডের Access Level কখনো কম নো বা সংকুচিত করা যাবে না (You cannot reduce the visibility of the inherited method)। বড়জোর এক্সেস লেভেল বাড়ানো বা সমান রাখা যাবে।

Topic 08

super Keyword & Parent Class Execution Flow

super কী?

super হলো একটি রেফারেন্স ভ্যারিয়েবল যা ইমিডিয়েট প্যারেন্ট ক্লাসের (Immediate Parent Class) অবজেক্টকে পয়েন্ট করে।

super এর ৩টি প্রধান কাজ:

  1. Parent Instance Variable Access: Shadowed প্যারেন্ট ভ্যারিয়েবল ব্যবহার করতে (super.variable)।
  2. Parent Overridden Method Invoke: প্যারেন্ট ক্লাসের ওভাররাইড হওয়া মেথড কল করতে (super.method())।
  3. Parent Constructor Call (super()): প্যারেন্ট কনস্ট্রাক্টর কল করতে (চাইল্ড কনস্ট্রাক্টরের ১ম লাইনে)।
💡 Constructor Execution Sequence:
যখন চাইল্ড ক্লাসের অবজেক্ট তৈরি করা হয়, প্রথমে প্যারেন্ট ক্লাসের কনস্ট্রাক্টর এক্সিকিউট হয়, তারপর চাইল্ড ক্লাসের কনস্ট্রাক্টর সম্পন্ন হয়!
SuperMechanics.java JAVA 
class Employee {
    String name = "General Employee";

    Employee(String name) {
        this.name = name;
        System.out.println("1. Employee Parent Constructor Executed.");
    }

    void work() {
        System.out.println("Employee is working on general tasks.");
    }
}

class Manager extends Employee {
    String name = "Manager Spec"; // Variable shadowing

    Manager(String fullName) {
        super(fullName); // Calling parent constructor (Must be 1st line)
        System.out.println("2. Manager Child Constructor Executed.");
    }

    @Override
    void work() {
        super.work(); // Invoke parent method
        System.out.println("Manager is managing team projects.");
    }

    void printNames() {
        System.out.println("Parent Name (super.name): " + super.name);
        System.out.println("Child Name (this.name): " + this.name);
    }
}

public class Main {
    public static void main(String[] args) {
        Manager m = new Manager("Kaesar Zulkarnain");
        System.out.println("--- Method Execution ---");
        m.work();
        System.out.println("--- Variable Access ---");
        m.printNames();
    }
}
Expected Output:
1. Employee Parent Constructor Executed.
2. Manager Child Constructor Executed.
--- Method Execution ---
Employee is working on general tasks.
Manager is managing team projects.
--- Variable Access ---
Parent Name (super.name): Kaesar Zulkarnain
Child Name (this.name): Manager Spec

প্যারেন্ট ক্লাসে যদি শুধু Parameterized Constructor থাকে এবং কোনো Default Constructor না থাকে, তবে চাইল্ড ক্লাসের কনস্ট্রাক্টরে কী বাধ্যবাধকতা তৈরি হয়?

Topic 09

Abstract Class vs Interface (Abstraction)

অ্যাবস্ট্রাকশন (Abstraction) কী?

প্রয়োজনীয় ফিচারসমূহ দেখিয়ে ভেতরের জটিল বাস্তবায়নের বিস্তারিত আড়াল করার প্রক্রিয়াকেই Abstraction বলে।

  • Abstract Class: আংশিক অ্যাবস্ট্রাকশন (0 to 100%)। এতে abstract এবং concrete (normal) উভয় মেথডই থাকতে পারে। new দিয়ে অবজেক্ট তৈরি করা যায় না।
  • Interface: শতভাগ অ্যাবস্ট্রাকশন (Java 8 এর আগে)। ফিল্ডগুলো ডিফল্টভাবে public static final এবং মেথডগুলো public abstract হয়। (Java 8+ এ default ও static মেথডও যোগ হয়েছে)।

Abstract Class vs Interface (Master Comparison Table):

বৈশিষ্ট্য Abstract Class Interface
Multiple Inheritance ❌ অর্জিত হয় না (extends 1 class) ✅ একাধিক ইন্টারফেস implements করা যায়
Variables Type Final, Non-final, Static, Non-static হতে পারে শুধুমাত্র public static final (Constants)
Methods Abstract & Concrete মেথড দুটিই থাকে Abstract, Default, and Static Methods
Speed/Performance দ্রুততর (Fast) সামান্য ধীরগতির (Indirection এর কারণে)
AbstractionDemo.java JAVA 
// Interface
interface Drawable {
    void draw(); // Automatically public abstract
}

// Abstract Class
abstract class Shape implements Drawable {
    String color;

    Shape(String color) {
        this.color = color;
    }

    // Concrete method
    void showColor() {
        System.out.println("Shape color: " + color);
    }
}

// Concrete Class
class Rectangle extends Shape {
    Rectangle(String color) {
        super(color);
    }

    @Override
    public void draw() {
        System.out.println("Drawing a colored Rectangle.");
    }
}

public class Main {
    public static void main(String[] args) {
        Shape shape = new Rectangle("Blue");
        shape.showColor();
        shape.draw();
    }
}
Expected Output:
Shape color: Blue
Drawing a colored Rectangle.
📝 Practice Task 9

Abstract Class এর কি Constructor থাকতে পারে? যদি অবজেক্টই না বানানো যায়, তবে এর কনস্ট্রাক্টরের কাজ কী?

হ্যাঁ, Abstract Class এর অবশ্যই Constructor থাকতে পারে! যদিও এর সরাসরি অবজেক্ট বানানো যায় না, তবে যখন চাইল্ড ক্লাসের অবজেক্ট তৈরি করা হয়, তখন চাইল্ড কনস্ট্রাক্টরের মাধ্যমে super() দিয়ে Abstract class-এর ভ্যারিয়েবলসমূহ ইনিশিওলাইজ করার জন্য এর কনস্ট্রাক্টর প্রয়োজন হয়।
