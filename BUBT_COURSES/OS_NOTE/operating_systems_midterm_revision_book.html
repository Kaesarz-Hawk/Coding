1.1 What Operating Systems Do: Views & Architecture

Chapter 1 & Note P1-2

সহজ বাংলা সামারি (Concept Clarification):

অপারেটিং সিস্টেম (OS) হলো ইউজার এবং কম্পিউটার হার্ডওয়্যারের মধ্যবর্তী একটি ব্রিজ বা মাধ্যম। এর দুটি মূল দৃষ্টিভঙ্গি (Views) রয়েছে:
• User View: ব্যবহারকারী চায় সহজ ব্যবহারযোগ্যতা (Ease of use/Convenience) এবং উচ্চ গতি (Good Performance); সে হার্ডওয়্যারের রিসোর্স কীভাবে ভাগ হচ্ছে তা নিয়ে মাথা ঘামায় না।
• System View: অপারেটিং সিস্টেম এখানে একজন Resource Allocator (CPU time, Memory space, File storage সুষ্ঠু বণ্টন করে) এবং Control Program (সিস্টেমকে এরর ও অনুপযুক্ত ব্যবহার থেকে রক্ষা করে)।

1. The Kernel

"The one program running at all times on the computer"। কম্পিউটার অন হওয়া থেকে বন্ধ হওয়া পর্যন্ত সার্বক্ষণিক মেমোরিতে রান করতে থাকে।

2. System Programs

অপারেটিং সিস্টেমের সাথে শিপড হয়ে আসে কিন্তু কার্নেলের অংশ নয় (যেমন: Shell, Task Manager, Device Drivers, File Managers)।

3. Middleware

অ্যাপ ডেভেলপারদের ডাটাবেজ, গ্রাফিক্স বা মাল্টিমিডিয়া সার্ভিস দেওয়ার সফটওয়্যার ফ্রেমওয়ার্ক (সাধারণত মোবাইল ও আধুনিক ওএসে থাকে)।

1.2 Booting Process, Interrupts & DMA Architecture

Exam 5 Marks

স্টেপ-বাই-স্টেপ বুটিং প্রসেস (Booting Flowchart):

Step 1 পাওয়ার বাটন প্রেস করলে মাদারবোর্ডে বিদ্যুৎ সরবরাহ শুরু হয়।
Step 2: POST ROM এ থাকা বায়োস (BIOS/UEFI) POST (Power-On Self-Test) রান করে।
Step 3: HW Check RAM, কীবোর্ড, ডিস্ক ইত্যাদি হার্ডওয়্যার সঠিকভাবে সংযুক্ত আছে কি না চেক করে।
Step 4: Bootstrap Bootstrap loader সেকেন্ডারি স্টোরেজ থেকে OS Kernel খুঁজে RAM-এ লোড করে।
Step 5: Daemons কার্নেল লোড হয়ে System Daemons চালু করে এবং সিস্টেম ইউজার মোডে রান করে।

DMA কী এবং কেন প্রয়োজন? (Why DMA?)

সাধারণত I/O ডাটা স্থানান্তরে প্রতি বাইটের জন্য CPU ইন্টারাপ্ট পায়। কিন্তু হাই-স্পিড ডিভাইসের ক্ষেত্রে যদি প্রতি বাইটে CPU কে থামানো হয়, তবে CPU অন্য কাজ করতেই পারবে না!

সমাধান হলো DMA: ডিভাইস কন্ট্রোলার সরাসরি মেইন মেমোরির সাথে বাফারের সম্পূর্ণ একটি ব্লক (Block) ডাটা স্থানান্তর করে দেয় CPU এর কোনো সাহায্য ছাড়াই। সম্পূর্ণ ব্লক ডাটা পাঠানো শেষ হলে মাত্র একটি সিঙ্গেল ইন্টারাপ্ট (One Interrupt per Block) তৈরি হয়। এতে সিস্টেমের Throughput (একক সময়ে কাজের পরিমাণ) বহুগুণ বৃদ্ধি পায়!

Polling vs Interrupt (পার্থক্য):

ফিচার Polling (পোলিং) Interrupt (ইন্টারাপ্ট)
কাজের ধরন CPU বারবার ডিভাইসকে গিয়ে জিজ্ঞেস করে তার কিছু লাগবে কি না। ডিভাইসের ডাটা রেডি হলে সে নিজে CPU কে সিগন্যাল দিয়ে ডেকে নেয়।
CPU এফিসিয়েন্সি CPU সময় অপচয় হয় (Busy-waiting)। CPU হাইলি এফিসিয়েন্ট থাকে।
হার্ডওয়্যার সাপোর্ট কোনো বিশেষ হার্ডওয়্যার লাগে না। Interrupt Controller (PIC/APIC) ও Interrupt Line প্রয়োজন।

1.3 Dual-Mode Operation, Multiprogramming & Multiprocessing

Core Architecture

Dual-Mode Operation (User Mode vs Kernel Mode)

সিস্টেম ও অন্যান্য ইউজারকে অনিচ্ছাকৃত বা ক্ষতিকর প্রোগ্রামের হাত থেকে বাঁচাতে হার্ডওয়্যার একটি Mode Bit প্রদান করে:
• User Mode (Mode bit = 1): সাধারণ ইউজার প্রোগ্রাম চলে। সরাসরি হার্ডওয়্যার বা মেমোরি স্পর্শ করার অনুমতি নেই।
• Kernel Mode / Supervisor Mode (Mode bit = 0): অপারেটিং সিস্টেম কার্নেল চলে। সব Privileged Instructions (যেমন: I/O নিয়ন্ত্রণ, টাইমার রিসেট, ইন্টারাপ্ট বন্ধ করা) এখানে এক্সিকিউট হয়।
• ইউজার প্রোগ্রাম যখন হার্ডওয়্যার সেবা চায়, তখন সে একটি System Call দেয়, ফলে হার্ডওয়্যার Trap জেনারেট করে মোড বিট ১ থেকে ০ তে রূপান্তর করে কার্নেল মোডে যায়। কাজ শেষে আবার মোড বিট ১ করে ইউজার মোডে ফেরত আসে।

পরীক্ষার ৫ মার্কসের স্পেশাল প্রশ্ন: "Why in shared systems Multitasking is more suitable than Multiprogramming?"
Multiprogramming (Non-preemptive): মেমোরিতে একসাথে একাধিক প্রোগ্রাম রাখা হয় কেবল CPU Utilization সর্বোচ্চ করতে। যখন রানিং জবটি I/O এর জন্য অপেক্ষা করে, কেবল তখনই CPU অন্য জবে সুইচ করে। কিন্তু কোনো জব যদি বড় ক্যালকুলেশন করতে থাকে, অন্য ইউজাররা অপেক্ষা করেই থাকে (No time-sharing).
Multitasking / Timesharing (Preemptive): CPU প্রতিটি ইউজার বা প্রসেসকে একটি নির্দিষ্ট Time Slice / Quantum দেয়। ফলে CPU এত দ্রুত সুইচ করে যে প্রতিটি ইউজার মনে করে কম্পিউটারটি শুধু তার একার জন্যই চলছে (Response time < 1s)। শেয়ার্ড সিস্টেমে একাধিক ইউজারের তাৎক্ষণিক রেসপন্স দিতে Multitasking ই সর্বোত্তম!
Symmetric (SMP) vs Asymmetric Multiprocessing:

• SMP: প্রতিটি প্রসেসর সমান এবং সবাই সমস্ত টাস্ক সম্পাদন করতে পারে।
• AMP (Master-Slave): একটি মাস্টার প্রসেসর অন্য স্লেভ প্রসেসরদের কাজ বরাদ্দ করে দেয়।

Multi-core vs Multiprocessor (হাতের লেখার নোট):

• Multiprocessor: মাদারবোর্ডে একাধিক সম্পূর্ণ ফিজিক্যাল CPU চিপ সংযুক্ত থাকে।
• Multi-core: একটি একক ফিজিক্যাল CPU চিপের ভেতর একাধিক প্রসেসিং কোর (Core 1, Core 2) বসানো থাকে।
সব Multi-core প্রসেসরই Multiprocessor, কিন্তু সব Multiprocessor মাল্টিকোর নাও হতে পারে!

3.1 Process Concept, Memory Layout, States & PCB

Chapter 3 & Notes

প্রোগ্রাম বনাম প্রসেস: প্রোগ্রাম হলো হার্ডডিস্কে সংরক্ষিত একটি প্যাসিভ ফাইল (Passive entity e.g., app.exe)। যখন এই এক্সিকিউটেবল ফাইলটি র‍্যামে লোড হয়ে রান শুরু করে, তখন তা সক্রিয় হয়ে Process (Program in execution - Active entity) এ রূপান্তরিত হয়।

[ Process in Memory Layout ]
  Max Address ┌───────────────────────────┐
              │           STACK           │ ──> Local vars, Func params (Grows Downward ↓)
              ├───────────────────────────┤
              │             ↓             │
              │                           │
              │             ↑             │
              ├───────────────────────────┤
              │           HEAP            │ ──> Dynamic allocation (`malloc`, `new`) (Grows Up ↑)
              ├───────────────────────────┤
              │           DATA            │ ──> Global & Static variables
              ├───────────────────────────┤
              │           TEXT            │ ──> Compiled Program Code (Instructions)
  0 Address   └───────────────────────────┘
5 টি প্রসেস স্টেট (Process States):
1. New: প্রসেসটি সবেমাত্র তৈরি হচ্ছে (Secondary Memory তে)।
2. Ready: প্রসেসটি RAM এ লোড হয়ে CPU পাওয়ার অপেক্ষায় কিউতে বসে আছে।
3. Running: CPU তে বর্তমানে প্রসেসটির নির্দেশাবলি এক্সিকিউট হচ্ছে।
4. Waiting (Blocked): কোনো I/O অপারেশন বা সিগন্যাল পাওয়ার জন্য অপেক্ষা করছে।
5. Terminated: প্রসেসটির কাজ সম্পূর্ণ হয়ে এক্সিকিউশন শেষ হয়েছে।

   [ NEW ] ─────( admitted by LTS )─────> [ READY ] <────────┐
                                              │              │
                                   (scheduler dispatch)  (interrupt)
                                              ▼              │
   [ TERMINATED ] <──────( exit )──────── [ RUNNING ] ───────┘
                                              │
                                        (I/O or event wait)
                                              ▼
                                         [ WAITING ] ──(I/O done)──> [ READY ]

Process Control Block (PCB) এর ভূমিকা ও উপাদান:

প্রতিটি প্রসেসের জন্ম থেকে মৃত্যু পর্যন্ত যাবতীয় বায়োডাটা বা স্টেট ধরে রাখার জন্য অপারেটিং সিস্টেম কার্নেল একটি করে PCB (Task Control Block) মেইনটেইন করে। এতে যা যা থাকে:

Process State New, Ready, Running ইত্যাদি
Program Counter পরবর্তী নির্দেশের এড্রেস
CPU Registers Accumulators, Index registers
Scheduling Info Priority, Queue pointers
Memory Limits Base & Limit registers, Page tables
Accounting Info CPU time used, time limits
I/O Status Info বরাদ্দকৃত I/O ডিভাইস এবং ওপেন করা ফাইলের লিস্ট

Context Switch কী এবং কেন এটি "Pure Overhead"?

যখন CPU প্রসেস $P_0$ থেকে প্রসেস $P_1$-এ সুইচ করে, তখন সিস্টেমকে $P_0$-এর বর্তমান অবস্থা তার $PCB_0$-তে সেভ করতে হয় এবং $P_1$-এর পূর্বের অবস্থা তার $PCB_1$ থেকে রিলোড করতে হয়। এই স্টেট সেভ ও রিলোড করার প্রক্রিয়াকে Context Switch বলে।
কেন একে Pure Overhead বলা হয়? কারণ কনটেক্সট সুইচ চলাকালীন সিস্টেম কোনো কাজের কাজ (Useful work) সম্পন্ন করে না; এটি কেবলমাত্র সিস্টেম অ্যাডমিনিস্ট্রেটিভ সময় নষ্ট করে।

3.2 Types of Schedulers (LTS, STS, MTS) & Degree of Multiprogramming

Direct Note Question
Job Scheduler

Long-Term Scheduler (LTS)

• সেকেন্ডারি স্টোরেজ (Job pool) থেকে কোন প্রসেসগুলো RAM-এর Ready Queue-তে প্রবেশ করবে তা নির্ধারণ করে।
• খুব ধীরে কল হয় (সেকেন্ড বা মিনিটে একবার)।
• Controls the degree of multiprogramming (মেমোরিতে মোট প্রসেস সংখ্যা নিয়ন্ত্রণ করে)।

CPU Scheduler

Short-Term Scheduler (STS)

• Ready Queue থেকে কোন প্রসেসটি এখন CPU পাবে তা বাছাই করে।
• অত্যন্ত ঘনঘন কল হয় (মিলি-সেকেন্ডে)।
• একে প্রচণ্ড দ্রুত (Super Fast) হতে হয় যাতে সিস্টেমে ল্যাগ না হয়।

Swapper

Medium-Term Scheduler (MTS)

• যখন RAM-এ অতিরিক্ত চাপ পড়ে যায়, তখন সাময়িকভাবে আংশিক রানিং প্রসেসকে মেমোরি থেকে ডিস্কে সরিয়ে দেয় (Swap-out)।
• পরে চাপ কমলে আবার ফিরিয়ে আনে (Swap-in)।
• Reduces the degree of multiprogramming to improve performance.

I/O-bound Process: ক্যালকুলেশনের চেয়ে I/O অপারেশনেই বেশি সময় কাটায়; অনেকগুলো ছোট ছোট CPU burst থাকে (যেমন: Text Editor, Web Browser).
CPU-bound Process: I/O কম করে জটিল গাণিতিক ক্যালকুলেশনেই বেশি সময় কাটায়; দীর্ঘ দীর্ঘ CPU burst থাকে (যেমন: Video Rendering, Scientific Simulation).

3.3 Process Operations (`fork`, `exec`, `wait`), Zombie vs Orphan & IPC

Viva & Midterm Favorite
fork()

প্যারেন্ট প্রসেসের হুবহু কপি করে নতুন চাইল্ড প্রসেস তৈরি করে। চাইল্ডে 0 এবং প্যারেন্টে চাইল্ডের PID রিটার্ন করে।

exec()

fork() এর পরে চাইল্ড প্রসেসের মেমোরিকে সম্পূর্ণ নতুন বাইনারি প্রোগ্রাম দিয়ে রিপ্লেস করে দেয়।

wait()

প্যারেন্ট প্রসেস ততক্ষণ স্লিপ/পজ থাকে যতক্ষণ না তার চাইল্ড প্রসেস এক্সিকিউশন শেষ করে এক্সিট স্ট্যাটাস দেয়।

exit()

প্রসেস তার শেষ স্টেটমেন্ট এক্সিকিউট করে অপারেটিং সিস্টেমকে সমস্ত বরাদ্দকৃত রিসোর্স রিলিজ করতে বলে।

Zombie Process কী?

যখন একটি চাইল্ড প্রসেস তার কাজ শেষ করে exit() হয়ে যায়, কিন্তু তার প্যারেন্ট প্রসেস এখনো wait() কল করেনি, তখন চাইল্ডের এক্সিট স্ট্যাটাস ধরে রাখার জন্য কার্নেলের Process Table-এ তার এন্ট্রি বা PID জমা থাকে। এমন জীবিত-মৃত অবস্থাকে Zombie Process বলে।

Orphan Process কী?

যখন কোনো প্যারেন্ট প্রসেস তার চাইল্ড প্রসেসের জন্য wait() কল না করেই নিজে টার্মিনেট বা বন্ধ হয়ে যায়, তখন চাইল্ড প্রসেসটি অভিভাবকহীন হয়ে পড়ে। একে Orphan Process বলে। লিনাক্সে এই এতিম প্রসেসকে স্বয়ংক্রিয়ভাবে রুট প্রসেস init (PID = 1) অথবা systemd দত্তক (Adopt) নেয়।

Inter-Process Communication (IPC): Shared Memory বনাম Message Passing

1. Shared Memory: • দুটি প্রসেস মেমোরির একটি কমন অংশ শেয়ার করে সরাসরি রিড-রাইট করে।
• সুবিধা: অত্যন্ত দ্রুতগতির (Maximum Speed), কারণ কার্নেলের কোনো হস্তক্ষেপ লাগে না।
• অসুবিধা: প্রসেসগুলোকে একই মেশিনে থাকতে হয় এবং একই সময়ে রাইট ঠেকাতে সিঙ্ক্রোনাইজেশনের দায়িত্ব ডেভেলপারকে নিতে হয়।
2. Message Passing: • প্রসেসগুলো কার্নেলের মাধ্যমে মেসেজ পাঠিয়ে যোগাযোগ করে: send(msg), receive(msg)।
• সুবিধা: ডিস্ট্রিবিউটেড সিস্টেম ও নেটওয়ার্কের বিভিন্ন মেশিনে থাকা প্রসেসের জন্য আদর্শ; কোনো শেয়ার্ড ভ্যারিয়েবল লাগে না।
• অসুবিধা: সিস্টেম কল ও কার্নেল ট্রানজিশনের কারণে গতি তুলনামূলক ধীর (Slower and costly)।

RPC কীভাবে কাজ করে?

• Client-side Stub: প্রক্সি হিসেবে কাজ করে। ক্লায়েন্টের দেওয়া প্যারামিটারগুলোকে নেটওয়ার্কে পাঠানোর উপযোগী প্যাকেটে রূপান্তর করে (একে Marshalling বলে)।

সার্ভার চালু হওয়ার সময় RPC রানটাইম রেজিস্ট্রিতে (Matchmaker/Daemon) নিজের সার্ভিস ও পোর্ট নম্বর রেজিস্টার করে। ক্লায়েন্ট সংযোগ করার সময় প্রথমে ম্যাচমেকারকে রিকোয়েস্ট করে নির্দিষ্ট পোর্ট নম্বর সংগ্রহ করে এবং এরপর সরাসরি সেই পোর্টে RPC যোগাযোগ চালায়।

1. Seek Time

ডিস্ক হেডকে কাঙ্ক্ষিত ট্র্যাক বা সিলিন্ডারে নিয়ে যেতে যে সময় লাগে (সবচেয়ে বড় সময় নেয়)।

2. Rotational Latency

কাঙ্ক্ষিত সেক্টরটি ঘোরার মাধ্যমে হেডের নিচে আসতে যে সময় লাগে। Average Latency = 1/2 × (60 / RPM).

3. Transfer Time

হেড থেকে কম্পিউটারে ডাটা স্থানান্তরের সময় = Data Size / Transfer Rate.

4. Controller Overhead

ডিস্ক কন্ট্রোলারের কমান্ড প্রসেস ও বাফারিংয়ের সময়।

SSD (Solid-State Disks): এতে কোনো স্পিন্ডল বা মুভিং হেড নেই (No moving parts), তাই Seek Time ও Rotational Latency শূন্য! ফলে HDD-এর তুলনায় কয়েক গুণ দ্রুত ডাটা রিড/রাইট করতে পারে।

Q3. What does fork() return to the parent and the child? If fork() is called 3 times sequentially in a C program, how many total processes and child processes are created?

১. fork() এর রিটার্ন ভ্যালু:
• Child Process-এ রিটার্ন করে: 0
• Parent Process-এ রিটার্ন করে: তৈরিকৃত নতুন চাইল্ডের PID (Process ID) (একটি পজিটিভ পূর্ণসংখ্যা)।
• কোনো কারণে চাইল্ড তৈরি ব্যর্থ হলে -1 রিটার্ন করে।

২. ৩ বার fork() কল করলে প্রসেস সংখ্যা:
সূত্র: $n$ বার fork() কল হলে মোট প্রসেস সংখ্যা হয় $2^n$।
এখানে $n = 3$, সুতরাং সর্বমোট প্রসেস সংখ্যা = $2^3 = 8$ টি।
এর মধ্যে মূল প্যারেন্ট প্রসেস ১টি, সুতরাং নতুন তৈরিকৃত চাইল্ড প্রসেস সংখ্যা = $2^n - 1 = 8 - 1 = 7$ টি।

Q4. What is a hardware Timer in Operating Systems? Why is setting the timer a Privileged Instruction?

টাইমার (Timer) কী? টাইমার হলো একটি বিশেষ হার্ডওয়্যার মেকানিজম যা একটি নির্দিষ্ট সময় পরপর CPU-কে ফিজিক্যাল ইন্টারাপ্ট সিগন্যাল পাঠায়। এটি Preemptive Multitasking বাস্তবায়নের মূল ভিত্তি।

কেন এটি Privileged Instruction? যদি সাধারণ ইউজার প্রোগ্রামকে টাইমার পরিবর্তন বা বন্ধ করার অনুমতি দেওয়া হতো, তবে কোনো অসাধু বা বাগযুক্ত প্রোগ্রাম (যেমন: while(1);) টাইমার বন্ধ করে অনন্তকাল CPU দখল করে বসে থাকতে পারত (CPU Hogging)। অপারেটিং সিস্টেম যেন কখনো তার নিয়ন্ত্রণ না হারায় এবং নির্দিষ্ট সময় পর পর ইউজার প্রোগ্রাম থামিয়ে CPU-র নিয়ন্ত্রণ ফেরত পেতে পারে, সেজন্য টাইমার সেট করার ক্ষমতা কেবলমাত্র কার্নেল মোডে (Privileged) রাখা হয়েছে।

Q5. Differentiate between CPU Scheduler and Dispatcher. What is Dispatch Latency?

Scheduler vs Dispatcher:
• CPU Scheduler (সিলেক্টর): রেডি কিউতে থাকা প্রসেসগুলোর মধ্য থেকে নির্দিষ্ট অ্যালগরিদম অনুযায়ী কোন প্রসেসটি পরবর্তী সময়ে CPU পাবে তা বাছাই (Select) করে।
• Dispatcher (এক্সিকিউটর): শিডিউলার যাকে বাছাই করেছে, তার হাতে CPU-র সম্পূর্ণ নিয়ন্ত্রণ তুলে দেয় (Gives Control)। এটি ৩টি কাজ করে: (১) Context Switch, (২) User mode-এ রূপান্তর, (৩) প্রোগ্রামের নির্দিষ্ট পয়েন্টে জাম্প করা।
Dispatch Latency: ডিসপ্যাচার কর্তৃক একটি রানিং প্রসেসকে থামিয়ে নতুন আরেকটি প্রসেসকে রান করাতে যে সময়টুকু ব্যয় হয়, তাকে Dispatch Latency বলে।

Q6. Explain the problem of Starvation (Indefinite Blocking) in Priority Scheduling and how "Aging" solves it.

Starvation (অনাহার / Indefinite Blocking): প্রায়োরিটি শিডিউলিংয়ে যদি সিস্টেমে ক্রমাগত উচ্চ প্রায়োরিটির (High priority) নতুন নতুন প্রসেস আসতে থাকে, তবে নিম্ন প্রায়োরিটির (Low priority) প্রসেসটি কখনো CPU পায় না এবং আজীবন রেডি কিউতে আটকে থাকে। একে Starvation বলে।
Aging (সমাধান): Aging হলো এমন একটি টেকনিক যেখানে কোনো প্রসেস সিস্টেমে যত দীর্ঘ সময় ধরে অপেক্ষা করতে থাকে, সময়ের সাথে সাথে তার প্রায়োরিটি ধীরে ধীরে এক ধাপ করে বাড়িয়ে দেওয়া হয় (যেমন: প্রতি ১৫ মিনিট অপেক্ষার জন্য প্রায়োরিটি ১ বৃদ্ধি পাবে)। এভাবে অপেক্ষা করতে করতে একসময় ঐ নিম্নমানের প্রসেসটিও সর্বোচ্চ প্রায়োরিটি অর্জন করে এবং নিশ্চিতভাবে CPU পায়!
